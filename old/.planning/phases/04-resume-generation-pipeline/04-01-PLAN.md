Replace the existing prompt (which uses `{{ job_description }}` full-text) with one that accepts structured JD fields. The updated prompt must:

- Accept `{{ master_resume_json }}` (full master resume as JSON string)
- Explicitly instruct: "Select ONLY from the provided master_resume content. Do not generate new experiences, projects, or skills that are not in the master."
- Ask LLM to rank and return a JSON object with:

  ```json
  {
    "ranked_experiences": [{"id": "<id>", "relevance_score": 0-10, "reason": "..."}, ...],
    "ranked_projects": [{"id": "<id>", "relevance_score": 0-10, "reason": "..."}, ...],
    "selection_rationale": "<1-2 sentence explanation>"
  }
  ```
- Note: skills are filtered separately by keyword matching (not by this prompt)
- Include line: "Do not include any text outside the JSON block."

The master_resume.json has experiences with id fields, and projects with title fields (use title as the id for projects).

**Step 3: Create src/resume/selection.py**

Implement `select_resume_content(job_record: JobRecord, master_resume: dict, llm_client: LLMClient, config: AppConfig) -> dict` as an async function.

Logic:
1. Extract JD fields from job_record. JobRecord has fields: `role`, `company`, `location`, `jd_text`. Since Phase 5 (JD parsing) hasn't run yet, the job_record at this stage will have basic fields. Extract what's available:
   - If `job_record.jd_text` is not None, do a simple keyword pass to extract skills (words that appear in master_resume technical_skills). Otherwise use empty lists.
   - Build `jd_payload` dict: `{"job_title": job_record.role, "company": job_record.company, "skills": [], "responsibilities": [], "qualifications": []}` — Phase 5 will enrich this; Phase 4 works with what's available.
   - Note in docstring: "jd_payload is intentionally sparse for Phase 4 — Phase 5 enriches job_record fields."

2. Load and render the select_resume prompt:
   ```python
   from src.llm.utils import load_prompt, extract_json
   prompt = load_prompt(
       "select_resume",
       jd_fields=json.dumps(jd_payload, indent=2),
       master_resume_json=json.dumps(master_resume, indent=2),
   )
   ```

3. Call LLM:
   ```python
   raw = await llm_client.call(prompt)
   ranking = extract_json(raw)
   ```

4. Extract top-N from ranking:
   - Sort `ranking["ranked_experiences"]` by `relevance_score` descending; take first 3
   - Sort `ranking["ranked_projects"]` by `relevance_score` descending; take first 2
   - For each selected experience id, look up the full experience dict from `master_resume["work_experience"]` where `exp["id"] == selected_id` (or first matching). Use `title` field for projects.

5. Skills keyword filter (Claude's Discretion — use keyword filter per RESEARCH.md):
   - Collect all skills from master_resume `technical_skills` (flatten all category lists)
   - If `jd_payload["skills"]` is non-empty, filter master skills to those present in JD skills (case-insensitive substring match)
   - If JD skills is empty (Phase 4 mode): return all master skills flattened
   - This is intentionally simple — validation in Plan 02 catches hallucinations

6. Assemble `selected_content` dict matching resume_json_template.json structure (this is the payload for render_resume_tex):
   - Must have keys: `meta`, `style`, `header`, `sections`
   - Populate `meta` and `style` from defaults matching resume_json_template.json (hardcode the standard values: 9pt, letterpaper, charter font, etc.)
   - Populate `header` from master_resume header fields (name, contact)
   - Populate `sections` with: education (always include all), technical_skills (filtered), work_experience (top 3 selected), projects_and_research (top 2 selected), extracurricular (always include all)
   - Read master_resume.json structure carefully — it will have the actual field names for these sections

7. Save to selected_resume.json:
   ```python
   import json
   from pathlib import Path
   job_dir = Path(job_record.job_dir)
   (job_dir / "selected_resume.json").write_text(json.dumps(selected_content, indent=2))
   ```

8. Return `selected_content` (the assembled payload dict ready for render_resume_tex).

**Imports needed:** `json`, `logging`, `pathlib.Path`, `src.llm.utils.load_prompt`, `src.llm.utils.extract_json`, `src.llm.client.LLMClient`, `src.config.AppConfig`, `src.models.job_record.JobRecord`

**Error handling:** If extract_json raises ValueError (LLM returned bad JSON), log the error and re-raise — caller (ResumeService in Plan 03) decides whether to retry.

**Important note on master_resume.json structure:** Before implementing, read `templates/master_resume.json` to understand the actual field names and IDs for experiences, projects, skills, education, and extracurricular sections. Map them correctly in the selection logic.
