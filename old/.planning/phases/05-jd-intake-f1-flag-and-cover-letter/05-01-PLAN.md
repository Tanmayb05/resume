<feature>
  <name>F1 Sponsorship Keyword Detector</name>
  <files>src/jd/service.py, tests/test_jd_service.py</files>
  <behavior>
    detect_f1_sponsorship(jd_text: str) -> Optional[bool]

    Returns:
      True   — JD contains positive sponsorship indicators (H-1B, OPT, will sponsor, visa sponsorship)
      False  — JD explicitly denies sponsorship (no sponsorship, must be citizen only, cannot sponsor)
      None   — No sponsorship keywords found, or signals conflict (ambiguous)

    Cases (input -> expected output):
      "We will sponsor H-1B visas for qualified candidates" -> True
      "H1B sponsorship available" -> True
      "H1-B welcome" -> True
      "OPT eligible candidates welcome" -> True
      "Work authorization supported" -> True
      "Visa sponsorship provided" -> True
      "We are open to sponsoring work visas" -> True

      "Must be a US citizen or permanent resident only" -> False
      "No visa sponsorship available" -> False
      "Cannot sponsor work authorization" -> False
      "Do not sponsor H-1B" -> False
      "Authorized to work in the US without sponsorship" -> False

      "We are looking for a Python engineer" -> None
      "optional requirement" -> None        # NO false positive on "opt"
      "opt-in to our newsletter" -> None     # NO false positive on "opt"
      "optional skills include Docker" -> None
      "opt-out of email" -> None

      "We sponsor H-1B but must already be authorized" -> None  # conflicting signals -> ambiguous -> None
  </behavior>
  <implementation>
    Create src/jd/__init__.py as empty package init.

    Create src/jd/service.py with detect_f1_sponsorship() as a module-level function.
    Do NOT create JDService class yet — that is Plan 02.

    Implementation pattern from RESEARCH.md Pattern 4:
    1. Normalize text: lowercase + re.sub to collapse H-1B/H1-B variants to "h1b"
    2. Define _POSITIVE_PATTERNS list with word-boundary regexes:
       - r"\bwill\s+sponsor\b"
       - r"\bsponsorship\s+(?:is\s+)?(?:available|provided|offered)\b"
       - r"\bvisa\s+sponsorship\b"
       - r"\bopt\b(?!\s*-?\s*(?:in|out|ional))"  # OPT but NOT opt-in/opt-out/optional
       - r"\bh1b\b"  # after normalization
       - r"\bopt\s+(?:eligible|authorized)\b"
       - r"\bauthorize[ds]?\s+to\s+work\b"
       - r"\bwork\s+authorization\s+(?:supported|provided)\b"
       - r"\bopen\s+to\s+sponsor(?:ing)?\b"
    3. Define _NEGATIVE_PATTERNS list:
       - r"\bno\s+(?:visa\s+)?sponsorship\b"
       - r"\bsponsorship\s+(?:is\s+)?not\s+(?:available|offered|provided)\b"
       - r"\bmust\s+be\s+(?:a\s+)?(?:us\s+)?(?:citizen|permanent\s+resident|pr)\b"
       - r"\bcitizens?\s+(?:and\s+)?(?:permanent\s+residents?\s+)?only\b"
       - r"\bno\s+work\s+(?:visa|authorization)\s+sponsorship\b"
       - r"\bauthorized\s+to\s+work\s+(?:in\s+the\s+us|without\s+sponsorship)\b"
       - r"\bcannot\s+sponsor\b"
       - r"\bdo\s+not\s+sponsor\b"
    4. Logic: has_negative XOR has_positive -> return False/True; both or neither -> return None

    Use re.IGNORECASE on all pattern searches (text is already lowercased but keep flag for safety).
    Module-level logger = logging.getLogger(__name__).
  </implementation>
</feature>
